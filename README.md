# Инцидент

Неофициальная русскоязычная адаптация карточной игры [Backdoors & Breaches](https://github.com/blackhillsinfosec/play.backdoorsandbreaches.com) (Black Hills Information Security / Antisyphon Training) для одного игрока. Игра выступает противником: тайно выбирает цепочку атаки, ведёт повествование и разыгрывает вводные. Игрок — защитник, у которого есть 10 ходов, чтобы восстановить цепочку.

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # тесты правил
npm run sim      # оценка играбельности (Монте-Карло, ~1 мин)
npm run build    # статическая сборка в dist/
npm run playtest # бот играет партии в браузере (нужны npm run dev и Chrome)
```

## Колоды

Базовая колода Core v3.1 и 8 расширений на её основе: Расширение B&B, Облачная безопасность, Datadog, DenSecure, Электросетевой кооператив, Huntress, Red Canary, Trimarc, а также режим «Всё сразу». Всего 324 карты, у каждой оригинальная картинка и русский текст. Испанская колода, старые версии базовой колоды и отдельная колода ICS/OT не переносились.

- Карты расширений транскрибированы с картинок (`scripts/merge-decks.mjs` собирает их в `src/data/decks/`, `scripts/effect-patches.json` — ручные правки эффектов).
- Эффекты вводных и консультантов описаны в данных (поле `effects`) и исполняются движком: модификаторы, пропуск хода, выбывание процедур, раскрытие и добавление скрытых атак, броски с развилкой, преимущество/помеха, выбор консультантов и т. д.
- Категории атак названы по русской локализации MITRE ATT&CK, принятой у Positive Technologies: «Первоначальный доступ», «Повышение привилегий и перемещение», «Закрепление», «Управление и контроль, эксфильтрация».

## Постмортем

После партии кнопка «Постмортем» на итоговом экране открывает шаблон разбора в формате blameless. Номер инцидента, колоду, итог, цепочку атаки (кто и на каком ходу раскрыл каждое звено) и хронологию ходов игра заполняет сама. Участники вписывают состав команды, резюме и выводы («что сработало», «что не сработало», «где повезло»). По каждому звену отмечают, есть ли ловящие его процедуры в их компании на самом деле, и почему звено не нашли. Последний блок — задачи: действие, ответственный, срок, тип. Черновик сохраняется в браузере, готовый документ скачивается или копируется как Markdown (`src/postmortem.js`).

## Тестирование

- `npm test`: правила движка, данные всех колод, генератор постмортема и стресс-тест. Стресс-тест (`test/fuzz.test.mjs`) прогоняет по 600 партий на каждую колоду (`FUZZ=…` меняет число) и после каждого хода проверяет, что игра не зависает, у каждой скрытой атаки есть процедура на столе, блокнот не вычёркивает настоящую карту, а победа засчитывается только при раскрытии всех слотов.
- `npm run playtest`: бот играет полные партии через интерфейс по каждой колоде (`GAMES=…`, `ONLY="Название колоды"`). Он проходит окна вводных и консультантов и после каждого хода сверяет стол с состоянием игры. Если есть расхождения или ошибки в консоли, команда завершается с кодом 1.

## Правила

- Капитан берёт по одной карте атаки из 4 категорий: первичное проникновение, продвижение и повышение привилегий, закрепление, C2 и эксфильтрация.
- Из 13 процедур обнаружения 4 случайные становятся «установленными» и дают +3 к броску.
- Каждый ход игрок применяет одну процедуру и бросает d20. Результат 11 и выше — успех. После применения процедура 3 хода на перезарядке.
- При успехе капитан раскрывает одну карту атаки, которую ловит эта процедура, в порядке цепочки атаки. Если ни одна нераскрытая атака этой процедурой не ловится, проверка считается чистой и исключает варианты в «Блокноте аналитика».
- Натуральные 1 или 20 и три провала подряд вызывают вводную.
- В начале игры есть 3 подсказки. Подсказка ничего не стоит: капитан описывает симптом одной из нераскрытых атак (что видят пользователи, админы или журналы), но саму технику не называет. Подсказки не повторяются. Успешное «Кризисное управление» добавляет ещё одну.

## Что изменено относительно оригинала

| Что | Оригинал | Здесь | Почему |
|---|---|---|---|
| Изоляция | Не ловит ни одну атаку | При успехе даёт +1 ход | Иначе это «мёртвая» карта |
| Кризисное управление | Нужно только для вводной «Pastebin» | При успехе даёт +1 подсказку капитана и снимает штраф −2 | Не раскрывает атак, но ход не пропадает впустую |
| «Это был пентест» | Завершает сессию | Как в оригинале, но её можно отключить в меню | Обрывает 13–19 % партий |
| Выбор раскрываемой карты | Решает живой капитан | Первая подходящая по цепочке атаки | Детерминированно и логично |
| Нечёткие вводные | — | «Политика?» убирает случайную процедуру насовсем (кроме «Кризисного управления»); «Удача SOC» раскрывает первую нераскрытую карту | В тексте карт это не уточнено |

## Оценка играбельности

`npm run sim` играет по 20 000 партий на каждую конфигурацию двумя моделями игрока:
- **новичок** выбирает доступную процедуру случайно;
- **аналитик** играет жадно: выбирает ход с максимальным произведением «шанс успеха × шанс раскрытия» с учётом перезарядки, бонусов и уже исключённых вариантов.

| Конфигурация | Новичок | Аналитик | Обрыв «пентестом» |
|---|---|---|---|
| Оригинальные правила | 25 % | 78 % | 13–18 % |
| **Адаптация, 10 ходов, с «пентестом» (по умолчанию)** | **26 %** | **78 %** | 13–19 % |
| Адаптация, 10 ходов, без «пентеста» | 31 % | 87 % | — |
| 8 ходов | 16 % | 65 % | 12–16 % |
| 12 ходов | 38 % | 83 % | 14–22 % |
| Бонус установленных +2 | 25 % | 76 % | 14–20 % |

Выводы:
- **Решения игрока важны.** Разница между случайной игрой и продуманной составляет около 55 п. п. Значит, это головоломка, а не просто кидание кубика.
- **10 ходов — удачная длина.** Продуманная игра обычно побеждает к 6–7-му ходу, так что остаётся запас на неудачные броски. Случайная игра чаще проигрывает. При 8 ходах заметно сложнее, при 12 — заметно легче. Отсюда три уровня сложности в меню.
- **Правки для «Изоляции» и «Кризисного управления» не ломают баланс:** разница меньше 0,5 п. п. Они добавляют выбор, а не силу.
- **Самая трудная категория — закрепление.** Её ловят почти только «Анализ средств защиты конечных точек» и «Анализ конечных точек». Карты «Сценарии входа в систему» и «Злоупотребление специальными возможностями ОС» обнаруживаются всего двумя процедурами.
- **«Изоляция» и «Кризисное управление» в оригинале не ловят ни одной атаки.** В настольной версии это работает за счёт обсуждения, в цифровой без доработки такие карты были бы ловушками.

## Почему Phaser 3, а не Three.js

Игра двумерная, карточная и на 80 % состоит из текста. Phaser 3 даёт готовые сцены, анимации, загрузчик и ввод для 2D-стола. Three.js пригодился бы для 3D-кубика или 3D-стола, но за счёт заметно большего объёма работы, а текст в WebGL на русском хуже по качеству. Поэтому стол, карты, переворот и бросок d20 рисует Phaser, а весь русский текст — журнал капитана, описания карт, меню и разбор — сделан обычным HTML поверх. Так кириллица остаётся чёткой и доступной, а вёрстка — адаптивной.

## Структура

- `src/core/` — правила без зависимостей от движка (`engine.js`), стратегии и шансы (`ai.js`), голос капитана с 64 русскими подсказками-симптомами (`narrator.js`). Этот код используют и игра, и симулятор.
- `src/data/cards.json` — 52 карты Core Deck v3.1: оригинальный и русский текст, детекты, инструменты.
- `src/BoardScene.js` — сцена Phaser. `src/ui.js` — HTML-интерфейс. `src/main.js` — связка.
- `sim/` — симулятор. `test/` — тесты правил.
